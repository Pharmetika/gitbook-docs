# 2025-12-26

## New Features:

* Sales Portal: a new portal for sales representatives to view and track activities related to their accounts has been added. On the pharmacy side new fields are available in reports for tracking sales rep assignments and commissions.
* MFA for pharmacy staff: Multi-factor authentication (MFA) has been added as an optional security feature for pharmacy staff logins. This can be enabled on a per-user basis in the user management section.
* Tableau Integration: A new integration with Tableau has been added to allow for advanced data visualization and reporting. A subset of dashboards are available embedded into Pharmetika. Additional visualizations and datasets are available with appropriate licensing.
* OTC Inventory Management: a new module for managing over-the-counter (OTC) inventory has been added. This includes features for tracking and managing stock levels, bulk imports for products and inventory, alternate checkout options, and the ability to set a default price in lieu of a price plan.

## Enhancements:

#### **Prescription Entry**

* Added button to print a backtag label from the prescription entry screen
* If Fill Upon Verification is enabled, this will now require that a bill-to option is selected before allowing the fill to be completed.
* A system setting has been added to control whether to require a bill-to selection be made during prescription entry verification.

#### **Prescription Fills**

* Added a button to remediate prescription fields which have been flagged during fill validation. One common use case is to update the prescription refills and expiration date when the prescription is being sent to a state which considers the medication a controlled substance.
* Added a warning message when attempting to ship a prescription that is considered a controlled substance to a state that is not configured to allow shipping of controlled substances.

#### **Dispense Queue**

* Added a copy button to patient name and DOB
* Added a View Medication History button on the dispense screen
* Added a days supply filter to the dispense queue
* Fixed an issue where a second dispense would default to the dispense quantity as the fill quantity

#### **Products**

* Added a Customer Description field for use in the patient portal and AI call center
* \[OTC Inventory Management] Added support for setting a default price when no price plan is applied to an OTC product
* \[OTC Inventory Management] Added support for bulk importing OTC products and inventory via CSV
* \[OTC Inventory Management] Added support for setting a UPC on a product for OTC products
* Added support for setting a default lot to decrement from when a lot\_identifier is not provided during checkout or dispense. This is useful for OTC products where lots are not tracked during checkout level (i.e. when a prescription is not created and dispensed).
* Added support for adding OTC items directly to checkout by barcode scanning of the product UPC. This will decrement inventory from the default lot for the product.

#### **Pricing & Price Plans**

* Added the ability to itemize refunds from a charge or invoice
* Added an organization level setting to control whether to apply organization pricing to patient paid prescriptions
* Added a report to display which price plan group is attached to each organization.
* Added additional audit logging to price plan/price plan group changes. This is available in the Audit Log section.
* When removing a price plan, the system will now display the resources impacted by the removal. This includes products, organizations, and price plan groups.
* The price plan being applied to a prescription/fill will now display at the top of the Pricing section on the prescription/fill details page.
* Invoicing: added 30/60/90 day aging buckets to be displayed on the invoice statement.

#### **Reporting & Metrics**

* Added report for listing replacement dispenses
* Added report to list tasks by date range and status
* Added additional filter options to Payment Transaction Itemized report
* Fixed an issue when generating larger (> 1GB) XLSX reports that would cause the report to fail

#### **Other Enhancements**

* Added a button to view the manifest on completed fills.
* Added audit logging for changes to orders. This is available in the Audit Log section.
* Orders: when a multi-patient order has more than 25 patients, a warning message will be displayed alerting the user that performance may be impacted. This is still supported, but large orders can be slower to process.
* Autoship: the N-th day of month option has been removed.
* Patient Handoff: The patient handoff screen has been redesigned and now allows multiple patients to be signed out at the same time.
* Practitioner Portal: Added a system setting to enable the invoice management permission by default for new practitioners.
* Practitioner Portal: Added an option to enable the invoice management permission on the invite screen for new practitioners.
* SMS compliance: To comply with new state regulations, SMS messages sent to patients in Texas will be blocked during mandatory quiet hours of 9pm to 8am. Messages sent from the patient Messages panel will still be sent, but automated messages from the system will be blocked during this time period.
* PMP Reporting: reporting to Utah has been migrated to the new Utah PUP system and updated to send in ASAP 5.0 format.
* Faxing: outbound faxing has been made more robust and will now failover to a secondary fax provider if the primary provider is unavailable.

#### **API Integrations**

* Added support for sending address\_id when sending a medication order. This can also be performed for electronic orders from an intermediary (e.g. SureScripts). This allows clinics to specify which address to use for the order when multiple addresses exist for the patient.
* Added an archived indicator when a duplicate patient profile is detected so that API consumers can choose to ignore archived profiles.
* BREAKING CHANGE: Added a warning when DOB is not provided in a valid format when submitting a medication order via API. Currently, this is only a warning, but a future change will mean that an invalid DOB would cause the order to be rejected. Now the order will be accepted, but a warning will be provided to the user/integration.

## Fixes:

* Quarantined Lots: Fixed an issue where quarantined lots did not properly record a date\_entered\_inventory.
