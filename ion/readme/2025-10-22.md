# 2025-10-22

## Enhancements:

### **Shipping and Handoff Enhancements**

* If you ship to destinations outside of the United States, you can now enter customs declaration information directly in the **Shipment Ready** window. When you click **Create Shipment**, the system sends the price, tariff code, and weight information to the carrier, making your international shipping workflows smoother. If you ship multiple items in a single shipment, you can fill out different customs declarations for each item.

<figure><img src="../.gitbook/assets/Customs declaration NEW.png" alt=""><figcaption></figcaption></figure>

* If you use a tablet to let patients sign for pickups, ION now supports multiple different pickup stations and devices. When requesting a pickup signature in the **Request Signature** window, the user can select a specific handoff user in the new **Handoff User** field to send the request to a specific user’s device. For more information, click [here](https://support-portal.pharmetika.com/articles/279639-require-signatures-for-pickups?preview=udustnzvfhbzxxxpegzrtojtellyli).
* To streamline shipping workflows, we’ve added a new action barcode for printing labels, which users can scan from the **Shipment Ready** window when creating a new shipment.

<figure><img src="../.gitbook/assets/Print Label.png" alt=""><figcaption></figcaption></figure>

* Sometimes, you might need to ship prescriptions to clinics in states for which you are licensed, but for patients whose home addresses are located outside of that state. In these cases, you can now select the clinic’s address instead of the patient’s address during filling. This change means the system doesn’t prevent you from filling and shipping these orders.

### **Prescription Workflow Enhancements**

* In the **Patient Prescription List** window, which appears when you click the **View Medication History** button in the **Prescription Entry** activity, filled prescriptions now show an informational icon. Hover over this icon to see the NDC and quantity for the fill.

<figure><img src="../.gitbook/assets/Patient Prescription List.png" alt=""><figcaption></figcaption></figure>

* The Product Group Dispensing feature, which was previously available only as an add-on feature, is now available to all pharmacies. For more information about this feature, click [here](https://support-portal.pharmetika.com/articles/506103-dispensing-and-verifying-a-group-of-fills?preview=ofpnzdnwpxrxurwnxqbpaitbdrunsp).
* If you use the **Fill Request** queue, your pharmacy users can send fill requests directly to the queue even without clinical screening requests by clicking the **Create Fill Request** button. This button is useful when most prescriptions require a pharmacist clinical screening review.

<figure><img src="../.gitbook/assets/Create Fill Request.png" alt=""><figcaption></figcaption></figure>

* To require pharmacy users and prescribers to enter additional context for prescriptions with a reason for compounding, select the new **Require Additional Context** checkbox in the **Product Options** section of a product. Note that this checkbox appears only when the **Require Reason for Compounding** checkbox is also selected.

<figure><img src="../.gitbook/assets/Require additional context.png" alt=""><figcaption></figcaption></figure>

* For enterprise clients, the Practitioner Portal can now upload multiple new patient profiles at one time from a TSV file. For more information, click [here](https://support-portal.pharmetika.com/articles/252957-create-multiple-new-patients-at-one-time?preview=zzxwqeenuwqtyopodilacnjvjoqede).

<figure><img src="../.gitbook/assets/Upload Patient List.png" alt=""><figcaption></figcaption></figure>

* You can now see and search by e-prescription order ID and message ID in the **Rx Entry** queue, which can make it easier to find and open the specific electronic prescription you’re looking for. Note that this feature already appeared in production at the time this changelog was released.

<figure><img src="../.gitbook/assets/eRX order and message ID search.png" alt=""><figcaption></figcaption></figure>

### **Administrative Reporting Enhancements**

* The **Prescriber State License List** report shows primary and secondary state licensure information for prescribers in your system, as well as expiration dates for those licenses. Compliance users can run this report to identify prescribers who are missing necessary state licenses or to remind prescribers of upcoming licensure renewals.

<figure><img src="../.gitbook/assets/Prescriber State License List report.png" alt=""><figcaption></figcaption></figure>

### **PMP Reporting Enhancements**

* A link to a PMP submission report in the **PMP Details** window helps give you greater visibility into a specific fill’s PMP status. This report, which is identical to the one you can open from the **Entry Link** column in the **PDMP Submission** report, shows you the exact data submitted to the state PMP for a fill, which can help you troubleshoot more complicated issues with submissions. Note that this feature already appeared in production at the time this changelog was released.

## Fixes:

* In scenarios where your users accidentally void a different fill than intended from the **Fill History** window, they can now more easily restore the voided fill by clicking the white **Fill Entry** button and refilling the prescription. This fix helps prevent your pharmacy from needing to submit a support ticket to change the status of the accidentally voided fill as described in the **Nuanced Voiding Scenarios and How to Resolve Them** header within the [Void a Fill or Dispense](https://support-portal.pharmetika.com/articles/233479-void-a-dispense?preview=taqsawzgzvrbvlzzclljzqlkxtsgkz) section.

<figure><img src="../.gitbook/assets/White fill entry.png" alt=""><figcaption></figcaption></figure>

* We’ve fixed an issue with refunding individual items from a payment. Now payments are refunded as expected when you select individual items in the Confirm Refund window.
